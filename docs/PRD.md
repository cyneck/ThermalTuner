## 1. 产品定位

### 1.1 要解决的问题

| 用户痛点 | 现状 | 本产品做法 |
|---|---|---|
| 机器烫、风扇吵，但不知道为什么 | 任务管理器只有负载，没有温度/功耗 | 常驻显示封装温度、包功耗、PL1 决策值 |
| 网上教程让你改 PL1，改完不知道有没有生效 | throttlestop 类工具参数裸露、无解释 | 决策可解释：每条策略给「规则 + 因果句 + 路径」 |
| 换了新 CPU 老工具就失灵 | 参数硬编码某一代平台 | 环境探测 → 推导约束 → 注入决策引擎，未知平台保守回退 |
| 改坏了没法恢复 | 无备份概念 | 写入前备份原值，退出/一键恢复，看门狗超时回滚 |

### 1.2 明确不做（本期）

- 不做 GPU / 内存 / 风扇曲线自定义（只做 CPU 封装热约束）
- 不做超频、电压调节（Undervolt 属高风险区，v2 再议）
- 不做云端账号、不做跨机同步
- 不主动关闭内存完整性（HVCI）来换取驱动可用性

## 2. 用户与场景

| 角色 | 特征 | 核心诉求 | 主路径 |
|---|---|---|---|
| 小白（60%） | 不懂 MSR/PL1 | 别烫、别吵、别搞坏 | 向导 → 推荐档 → 只看概览 |
| 进阶（30%） | 知道 PL1/PL2 含义 | 想微调 + 看效果 | 智能调优 → 改天花板 → 观察曲线 |
| 极客（10%） | 要精确控制 | 直接改参数、要 diff 和回读 | 高级参数 → 解锁 → 应用 → 校验 |

典型场景：编译/渲染长任务时机器降频 → 打开工具看到「温度 89°C 触顶 → PL1 从 44W 降到 38W」→ 切静音档降噪 → 任务结束退出恢复原值。

## 3. 已锁定产品决策（本期不再讨论）

| # | 决策 | 结论 | 理由 | 影响范围 |
|---|---|---|---|---|
| D-01 | 是否装完即自动写 MSR | **向导推荐后需用户确认；日常运行免打扰** | 写硬件不可逆，首启必须让用户有感知；确认后长期静默 | 向导末步、设置页「自动接管」开关 |

| D-03 | 采样与常驻 | **1s 采样 + 托盘常驻** | 热控对延迟敏感；2s 会漏掉瞬时 PROCHOT | 主循环、托盘、CPU 占用预算 <1% |

## 5. 关键流程

### 5.1 首次启动向导（4 步，可跳过）

| 步 | 内容 | 用户动作 | 系统行为 | 失败出口 |
|---|---|---|---|---|
| 1 | 识别设备 | 无（自动） | 探测 CPU/形态/核心数/虚拟化，展示推导出的 TjMax 与 PL 区间 | 未知平台 → 显示「保守基线」并继续 |
| 2 | 权限与驱动 | 点「以管理员重启」 | 检测 PawnIO / LHM 可用性 | 无驱动 → 提供安装链接 + 「仅监控」继续 |
| 3 | 基线测量（20s） | 等待或跳过 | 采集轻载/负载两点，拟合热阻 Rth | 拟合失败 → 不阻塞，进入手动档 |
| 4 | 推荐档位 | 选「采用推荐」或手动 | 按预测稳态温度给建议档 + 是否启用自动接管 | 用户拒绝 → 保持只读 |

> 验收：新用户 3 次点击内进入主界面；任一步失败都能继续。

### 5.2 日常监控（默认态）

1. 1Hz 读封装温度 / 包功耗 / 负载 / 最高核频
2. 温度有效 → 更新热阻模型（最小二乘，R²≥0.5 且 ΔP≥12W 才采信）→ 决策树求值 → 更新 PL1/PL2/EPP/风扇目标
3. 写决策凭证到流水（保留最近 500 条）
4. 命中超温 / PROCHOT / 驱动掉线 → 事件中心 +1 角标

### 5.3 调参写入

1. 参数页默认只读 → 点「解锁编辑」（提示风险）→ 进入编辑态
2. 边输边校验（见 §8），非法项行内红字 + 禁用「应用」
3. 点「应用」→ 二次确认弹窗：列出 diff、备份说明、看门狗承诺
4. 确认 → 备份原值 → 限幅写入 → 回读校验 → 结果横幅（成功/部分成功/失败并自动回滚）
5. 失败必须回滚到备份值并给出原因

### 5.4 恢复原值

1. 设置页或参数页点「恢复原值」
2. 弹窗要求**输入「恢复」**二字才可提交
3. 恢复后回读校验，写审计日志

## 6. 应用状态机

| 当前态 | 触发 | 下一态 | 副作用 |
|---|---|---|---|
| Idle | 开始监控 / 启动自启 | Monitoring | 启动定时器，读遥测 |
| Monitoring | 用户停止 / 退出 | Idle | 停止定时器；若开启「退出恢复」→ Restoring |
| Monitoring | 一键标定 | Calibrating | 轻载基线 12s → 满载至温度平台（≤150s）→ 稳态采样 10s |
| Calibrating | 完成 / 取消 / 超时 | Monitoring | 拆除负载；两点稳态 ΔT/ΔP 写入 Rth，并询问是否应用推荐档 |
| Monitoring | 应用参数 | Applying | 备份 → 写入 → 回读 |
| Applying | 校验通过 | Monitoring | 更新「已生效」参数集 |
| Applying | 写入失败 / 回读不一致 | RollingBack | 用备份值重写 |
| RollingBack | 完成 | Monitoring（带错误事件） | 事件中心记 Error |
| 任意 | 驱动掉线 / 权限丢失 | Degraded | 顶部状态条转黄，决策暂停，仅显示负载 |
| Degraded | 恢复可用 | Monitoring | 重新初始化遥测 |

## 7. 异常与降级矩阵

| 异常 | 检测方式 | 界面表现 | 用户出口 | 决策是否继续 |
|---|---|---|---|---|
| 未装 PawnIO / 驱动被 HVCI 拦 | LHM 温度全 null + 功耗 0 | 顶部状态条黄：`温度不可用` | ① 安装 PawnIO ② 仅监控模式 | 否（无温度不决策） |
| 非管理员 | 令牌检测 | 状态条黄：`受限权限` | 以管理员重启 | 仅负载监控 |
| 未知 / 虚拟化平台 | 探测 Generation=0 或 VM | 状态条蓝：`保守基线` | 查看支持列表 / 继续 | 是（保守区间） |
| 传感器掉线（运行中） | 连续 3 拍 NaN | 状态条红 + 事件 | 重连 / 查看诊断 | 暂停 |
| MSR 被 BIOS 锁定 | 写后回读不一致 | 应用结果：`固件锁定，写入未生效` | 只读使用 / 查 BIOS 设置 | 是（只读） |
| 固件周期性回写 PL | 每 5s 回读比对漂移 | 参数页标注 `被固件接管` | 提示「本机固件接管功耗，工具仅观测」 | 是 |
| 拟合失败 / R² 不足 | 估计器拒绝 | 热阻显示 `--` | 继续用默认 Rth=0.8 | 是（不预测） |
| 用户中止 / 断电恢复 | 启动时检测脏标记 | 提示「上次未正常退出，已恢复原值」 | 一键确认 | 是 |

## 8. 参数与校验规则

| 参数 | 范围来源 | 规则 | 违反级别 | 文案 |
|---|---|---|---|---|
| PL1（持续功耗） | `HardwareLimits.MinPL1..MaxPL1`（探测推导） | 必须在区间内 | Block | `PL1 超出硬件允许范围 [15W, 90W]` |
| PL2（短时功耗） | `MinPL2..MaxPL2`，且 ≥ PL1 | 双条件 | Block | `PL2 (30W) 不能小于持续功耗限制 PL1 (35W)` |
| Tau（时间常数） | 合法 MSR 编码集 {1,2,4,8,16,28,32,64} | 只能取值集 | Block | `Tau (5s) 不是合法的硬件 MSR 编码步长` |
| EPP | 0..255 | 整数 | Block | `EPP 能量性能偏好必须在 [0, 255] 之间` |
| 温度天花板 | 40..TjMax | > `MaxSafeCeiling`(TjMax-5) 仅警告 | Warn | `目标温度天花板 (98°C) 超出最高安全建议值 (95°C)` |
| 风扇上限 | 0..100，按档位封顶 | 超档位上限降为档位值 | Warn | `静音档风扇上限 55%，已自动下调` |

> 校验器必须复用 `ThermalPilot.Core.ParamConstraints.Validate`，UI 不重复实现规则。

## 9. 安全护栏（写入通道的硬性要求）

| # | 护栏 | 要求 |
|---|---|---|
| G-01 | 备份 | 任何写入前把当前 MSR 原值落盘 `backup/msr-{timestamp}.json`，含 CPU 标识与校验和 |
| G-02 | 限幅 | 写入值先经 `HardwareLimits` 与 `ParamConstraints` 双重钳制，越界直接拒绝而非静默裁剪 |
| G-03 | 回读校验 | 写后 200ms 回读，与目标值比对；不一致即判定失败并回滚 |
| G-04 | 看门狗 | 进程异常退出/崩溃后 3s 内由恢复线程写回原值；用「脏标记 + 下次启动检查」兜底 |
| G-05 | 退出恢复 | 「退出时恢复原值」默认开启（D-01 的配套） |
| G-06 | 审计 | 每次写入/回滚记录时间、参数、前后值、结果，保留 30 天 |
| G-07 | 禁用场景 | 虚拟化、未知平台、电池电量 <20%、温度读数不可用时禁止写入 |
| G-08 | 冷却保护 | 温度 > TjMax-3 或 PROCHOT 期间禁止提升 PL1，只降不升 |

## 11. 非功能性要求

| 类别 | 指标 |
|---|---|
| 性能 | 空闲 CPU <1%（1Hz 采样）；内存 <300MB（Debug 实测 ~230MB，含 LHM 传感器枚举）；启动到首屏 <2s |
| 兼容 | Windows 10 1809+ / 11 x64；Intel 6 代~Core Ultra、AMD Zen+ 尽力支持；未知平台保守回退不崩 |
| 权限 | 只读监控可普通用户；温度需管理员 + PawnIO；无权限时明确降级，不静默失败 |
| 稳定 | 任何传感器/驱动异常不得导致进程崩溃（全部 try-catch + 降级） |
| 体积 | 安装包 <20MB（框架依赖发布）；单文件 <10MB |
| 可访问性 | 焦点可见、Tab 顺序合理、所有图标配文本、关键按钮对比度 ≥4.5:1、Esc 关弹窗 |
| 许可 | LHM（MPL-2.0）、PawnIO（按其发行许可）在设置页「许可」列出；分发前复核 |
| 本地化 | 中文为主，字符串集中管理便于后续 i18n |

| AC-12 | 写入回读 | 回读不一致显示失败并自动回滚，事件中心记 Error |
| AC-13 | 恢复原值 | 必须输入「恢复」才可提交 |
| AC-14 | 崩溃兜底 | 强杀进程后重启提示「上次未正常退出，已恢复原值」 |
| AC-15 | 热阻稳健 | 噪声数据下不产生假预警（R²<0.5 时不预测） |
| AC-16 | 标定 | 两段式稳态标定：轻载 12s + 满载至温度平台（10 拍波动 < 0.6°C，上限 150s）+ 稳态采样 10s；需实测功耗（RAPL/LHM），仅有估算功耗时禁用并说明原因；成功后给出 Rth 与档位推荐并可一键应用 |
| AC-17 | 曲线 | 温度/功耗双轴，1 小时窗口滑动，峰值标记可读 |
| AC-18 | 导出 | CSV 含时间/温度/负载/功耗/PL1/规则列，Excel 打开无乱码 |
| AC-19 | 事件中心 | 超温/掉线/PROCHOT 聚合，角标计数与列表一致 |
| AC-20 | 托盘 | 关闭窗口最小化到托盘，托盘菜单可切档与退出恢复 |
| AC-21 | 退出恢复 | 勾选项开启时退出后 MSR 与原值一致（回读验证） |
| AC-22 | 权限降级 | 普通用户启动不报错、不弹 UAC 死循环 |
| AC-23 | 许可 | 设置页可查看 LHM/PawnIO 许可文本 |
| AC-24 | 稳定性 | 连续运行 8 小时无内存增长 >20MB、无崩溃 |

## 16. M3 替代路径（研发下一步选型）

实测结论：`ioctl_write_msr` 在该签名模块中不可用（写返回 0x80070002，读正常）。三条可行替代：

| 方案 | 说明 | 代价 | 风险 |
|---|---|---|---|
| A. 官方可写模块 | 向 PawnIO 申请/等待支持写 0x610 的签名模块 | 依赖上游 | 低 |
| B. Intel DTT / OEM WMI | 走厂商 Dynamic Tuning 接口下发 PL1/PL2 | 机型适配量大 | 中 |
| C. Windows 电源方案 | powercfg 改 PROCTHROTTLEMAX / 睿频模式，官方支持、无需驱动 | 粒度粗（按频率百分比） | 低 |

建议：C 作为兜底先上（覆盖全机型、可回滚、无需签名），A 到位后再提供精确 PL 控制，B 只做明确需求的机型。
