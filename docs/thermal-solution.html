一、识别问题：判定树定位到具体环节

检测模块（tools/detect.py）输出一个 scene 场景码和一条 verdict 结论。五个可能结果：

二、原因解释：每个场景「为什么热」

tim_fault 硅脂断链（本机实测案例）

本机：R1 = 1.76 K/W（正常 7 倍），R2 = 0.32（健康），满载 96.7℃ 贴墙

原因：die 到散热器之间的硅脂干涸或压装不实，热阻从正常 0.1~0.35 涨到 1.76。热量堵在芯片里，风扇转速再高也吹不到结温——因为风扇只能影响 R2，而 R2 是健康的。

证据链：早期 40W → 稳态 35W 的功率回落（P_sag=2.9W）+ 97% 样本贴 95℃ = 温度墙在持续削功率。35W 不是电气 PL，是热的墙。

解决：硬件——重涂硅脂 / 重新压装（一次到位，反事实：换硅脂后 50W 满载 ≈ 48℃）。软件——降功率保命（限睿频、降目标温度）。

fan_fault 风扇/风道

原因：R2 偏高（>0.7），且把风扇从 60% 拉到 100% 温度几乎不降（ΔT < 6℃）——说明风量已经到顶或风道堵死。

解决：清灰 / 检查风扇转速 / 疏通出风口。软件在修复前降功率避开过热。

overall_weak 整体不足

原因：R1 和风扇都正常，仍然贴墙——散热规模（热管数、鳍片面积）对这台机器的功率设计不够，或环境温度过高。

解决：软件压功率到散热能力之内；硬件考虑散热底座或降低室温。

power_limit 电气墙

原因：温度远没到墙，功率却上不去——PL/供电/适配器限制。散热完全没问题，性能释放被电气参数卡住。

解决：查 PL 设置、供电、适配器；软件可适当放开功耗墙。

三、三档散热模型：静音 / 平衡 / 性能

识别出问题后，用户选一档，策略引擎（tools/thermal_policy.py）给出三个旋钮：温度上限、风扇上限、功率预算。注意：温度上限是「允许热到什么程度」的约束，不是「要压到多少」的目标——温度是功率乘热阻的结果，不是原因。

图 · 三档旋钮对比：平衡为默认，居中兼顾性能与噪声

三档旋钮如何决定功率预算

P_budget = (T_ceiling − T_amb) / (R1 + R2(fan_max))

两个变量方向相反：温度上限越高 → 功率预算越大；风扇占空比越高 → R2 越小 → 功率预算也越大。所以"性能档"应当同时具备"上限高 + 风扇满"，而不是把温度上限压低。

档位温度上限风扇上限功率预算（相对）噪声
静音88℃55%最低最低
平衡88℃75%中中
性能90℃100%最高最高

关键：性能档的功率预算最高。它靠「风扇 100%（R2 最小）+ 允许温度到 90℃」把预算做大，而不是把温度压到最低。静音与平衡共用 88℃ 上限，只靠风扇/EPP/PL2 区分——这样「想安静」不会顺带把性能削掉。

v1.3 曾把性能档温度设为 75℃（三档最低），结果 P_budget=(75−24)/R 也是三档最小，「性能模式」反而风扇最响、功率最低、频率最低。v1.4 已修正。

默认平衡档的「噪声别太大太久」如何落地

平衡档（默认）通过三个旋钮实现「保持性能 + 噪声可控」：

  • 风扇上限 75%——不超过 75% 占空比，避免全速呼啸；
  • 温度上限 88℃——与静音档同一条上限，但风扇更积极（75% vs 55%），所以实际温度更低、功率预算更大；
  • 空闲风扇 30%——低负载时风扇降到底速，噪声不会「持续太久」，只在真正发热时才提速。

三档旋钮如何落到硬件：精细调控优先级

上一版的「功率预算」只是抽象目标，真正生效的是 CPU/GPU 的 MSR/驱动级控制字。关键纠偏： 本机实测 powercfg PROCTHROTTLEMAX 无效（写值读得回，CPU 不认）， Windows 电源管理只是粗层且在本机失效；真正能精细平衡性能和散热的是 ThrottleStop/直接写 MSR（CPU 第 2 层）与 nvidia-smi/Afterburner（GPU 第 3 层）， PL1/PL2/Time（MSR 0x610）、降压（MSR 0x150）、Speed Shift EPP（MSR 0x773）。 以下 6 个旋钮按「性能代价最小」逐级动用（GPU 单独在第 3 层，见下方）：

图 · 精细调控优先级：①降压（无损）→ ②风扇（只增噪）→ ③EPP（软）→ ④PL1（硬削频）→ ⑤PL2（突增多高，与⑥独立）→ ⑥Time/τ（持续多久，与⑤独立）

控制面分层（哪些参数软件可控，哪些不可控）：

层名称可控工具说明
0硬件固有❌物理换件TDP / R1(硅脂) / 散热模组 —— 软件只能识别或绕开（如 deep1 靠降功率）
1Windows 电源管理（粗）✅powercfg本机 PROCTHROTTLEMAX 实测无效，粗杠杆
2CPU 精细调控（细）★主力✅ThrottleStop / MSR降压0x150 / PL1·PL2·Time 0x610 / EPP 0x773 / 睿频倍率 0x1AD
3GPU 精细调控（细）✅nvidia-smi / Afterburner功率墙% / 频率偏移 / 电压曲线 / 温度目标（独立于 CPU）
4外部（仅识别）❌—环境温度 / 散热底座·支架 —— 改不了，只当输入或建议

一句话：异常识别跑在「出厂默认逻辑」（第 1 层）只观察；调控伸到第 2/3 层 MSR/驱动级，而不是只有 Windows 自带的电源管理。 第 0/4 层不可软件控制，只能物理改或当输入。

真实机 deep1（R1=1.76 硅脂断链）求解结果（tools/control_model.py）：

档位降压风扇≤EPPPL1预测温度预测性能
静音−80mV55%200—87.7℃100%
平衡−80mV75%49—82.0℃92%
性能−80mV100%111—75.0℃83%

核心发现：这台机器靠 −80mV 降压 就把 96.7℃ 压到 87.7℃ 且 性能 100%、风扇仅 55%—— 降压是「性能无损降温」的救命杠杆；只有在温度上限用尽、仍超温时才动 EPP 软调，最后才用 PL1 硬削频。

四、完整闭环：本机实测示例

输入：lab-data/lab-deep1-20261028-191903.csv（本机 19 分钟实测）

判定：TIM/压装断链（重度）· R1 = 1.76 K/W
档位温度上限风扇≤功率预算说明
静音 ←推荐88℃55%29.9W故障未修前，静音保命
平衡88℃75%30.4W—
性能90℃100%32.0W—

为什么推荐静音？因为 R1 已重度断链，风扇对 R2 的作用被「卡死」的 R1 挡住，硬拉风扇只增噪声不降温。此时最合理的是静音档：限功率（29.9W）、压风扇（≤55%），把机器稳定在 88℃ 以内运行，同时噪声最低，直到用户换硅脂。注意三档预算只差 29.9 / 30.4 / 32.0W——R1 断了以后风扇几乎挣不到余量，这也是"该换硅脂"的直接证据。

健康机的对比（sim-healthy，R1=0.21）：三档功率预算分别是 108.3W / 115.3W / 129.4W（静音/平衡/性能），单调递增——R1 正常时风扇才真的有用，性能档靠"满转速 + 90℃ 上限"把预算做到最大。

五、代码入口

python tools/thermal_policy.py lab-data/xxx.csv --design-w 50 --tamb 24 # 输出：判定 + 场景 + 推荐档 + 三档温度上限/风扇/功率预算

一站式调用：

from thermal_policy import solve res, policy = solve("lab-data/xxx.csv", design_w=50, t_amb=24) # res = 检测结果（verdict/scene/features） # policy = 三档策略（recommended + profiles 三档旋钮）

检测模块 tools/detect.py、精细调控求解器 tools/control_model.py 与策略引擎 tools/thermal_policy.py 均为纯函数、无副作用，可直接集成到产品运行时。独立跑精细调控求解：

python tools/control_model.py lab-data/xxx.csv --mode balanced --design-w 50 --tamb 24 # 输出：降压 mV / EPP / PL1 / PL2 / tau / 等效频限 / 预测温度 / 预测性能 / 分步说明
