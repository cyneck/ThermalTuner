散热问题检测识别算法

ThermalPilot · 检测模块 · 5 分钟压测 → 定位故障环节

这套算法回答一个问题：一台「满载就 97℃」的机器，到底哪个环节坏了？

答案是靠一个物理模型 + 一棵判定树。整个过程分三步：

  1. 采数据——跑 5 分钟压测，记录温度、功耗、风扇占空比随时间的变化轨迹。
  2. 算特征——把轨迹压成 4 个物理量：R1（硅脂热阻）、R2（散热器到环境热阻）、ΔT（风扇杠杆）、pin（贴墙占比）。
  3. 走判定树——按序比对阈值，定位到具体环节，给出「换硅脂 / 清灰 / 压功率 / 健康」结论。

一、物理模型：一条热路，两个「关卡」

把芯片想成一块发热的「热源」，热量要经过两道关卡才能散到空气里：

图 1 · 两热阻模型：热量串过 R1、R2 两道关卡，风扇只能管第二道

温度公式很简单：

T_die = T_amb + (R1 + R2) × P

P 是功耗，R1、R2 是两道关卡的热阻（单位 K/W，即「每瓦功率抬升多少度」）。

核心洞察：稳态下 R1 和 R2 总是加在一起出现，光看温度根本分不清是谁坏了。就像一条堵车的路，你不知道是「路口 A」堵还是「路口 B」堵。

二、关键一招：怎么把 R1、R2 分开？

答案是抓「掉载瞬间」那一下：芯片热容小（1 秒就冷），散热器热容大（100 秒才冷）。压测突然停止时——

图 2 · 掉载瞬间：芯片秒跌、散热器还没动，温差就是 R1 的「指纹」

掉载后的 1~6 秒里，功率已经掉下去了，但散热器还热着没来得及冷。这一瞬间：

R1 = (T_段末 − T_过渡) / (P_段末 − P_过渡)

这个公式不需要知道环境温度、不受风扇影响，5 分钟就能测准（真机实测 1.76，与手算一致）。有了 R1，剩下的 R2 = Rtot − R1 也就顺势拆出来了。

一句话：稳态拆不开，就用「瞬态」拆。这就是整套算法最巧的地方。

三、判定树：四个关卡按序排查

特征算出来后，走一棵可解释的判定树，按「硅脂 → 风扇 → 整体 → 电气」的顺序排查：

图 3 · 判定树：从上到下按序排查，命中即停，输出对应故障环节
节点判据结论动作
N1R1 ≥ 0.8 K/W（≥1.4 重度）硅脂/压装断链重涂硅脂 / 重压装
N2R2 ≥ 0.7 且 ΔT(风扇60→100) < 6℃风扇/鳍片/风道清灰 / 换风扇 / 疏通风道
N3贴墙 ≥50% 且 R1 正常整体散热不足软件压功率
N4P ≤ 0.85×设计功率 且不贴墙电气功率墙散热无恙，查 PL/供电
N5都不命中健康可做精细优化

两个防误判设计（很重要）：

  • R2 是主判据、ΔT 只做确认——5 分钟档渐近线外推误差 ±2~3℃，但 R2 误差只有 ±0.1，更可靠。
  • 贴墙时风扇会被「掩盖」——机器贴着温度墙跑时，加风量温度也不降，会被误判成风扇坏。所以当 pin 高时，N2 自动改报「被掩盖」，先去修 N1/N3。

四、验证结果：40/40 全对

用 4 个仿真场景（物理参数已知，相当于「标准答案」）+ 真实机器数据，各换 10 个随机噪声种子共 40 次，全部正确分类：

场景R1R2判定
健康（50W 全额释放）0.210.53✅ 健康
风道堵0.261.25✅ 风扇/鳍片/风道
硅脂干涸（真实机参数）1.830.14✅ TIM 重度
电气墙0.240.49✅ 电气功率墙
真实 deep1（本机）1.760.32✅ TIM 重度 + 温度墙限功率
