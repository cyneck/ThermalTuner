## 一、评估口径与证据边界（先说清楚哪些结论能下、哪些不能）

1. **悬浮提示是静态截图拍不到的**：ToolTip 需鼠标 hover 才渲染。本文对 ToolTip 的判定依据是 `*.xaml` 绑定源 + `SessionState.cs` / `EnvironmentCheck.cs` 的实际文本生成逻辑 + 控件启用状态，不是从图片上读字。
2. **本次全程为「普通用户」态**：顶栏显示「普通用户」，写入闸门未开，包功耗来源为 WMI 估算，风扇 / 最高核频 / 实测 PL1 均为 N/A。因此**管理员态下的「选中档位下发、手工保存写入、一键标定、解锁编辑」主流程未实测**，相关结论只针对「降级态的表达是否清楚」。
3. **架构基线已变更**：`11dee75` 把 MSR 通道从 WinRing0 / LHM 0.9.4 迁到 **PawnIO 直连 IOCTL + LHM 0.9.6**，并在包内自带 PawnIO 驱动与可写 IntelMSR 模块。本项目旧笔记中「LHM 必须固定 0.9.4」的约束**已作废**；下文按新架构判定文案准确性。
4. **截图工具覆盖不全**：`--height 1800` 与 `--height 2600` 均只输出 `1306x1132`，诊断页底部「固件基线与三层参数对照」卡片被裁切。该限制本身已列为 UX-18。
5. **工作树有未提交改动**（`EcPortReader.cs`、`HardwareTelemetry.cs`、`README.md` 修改，新增 `FanSources.cs` / `FanSource.cs` / `FanSourceTests.cs`），风扇相关判定以当前快照为准，可能随该改造变化。

## 二、结论摘要

| 维度 | 判定 | 一句话说明 |
|---|---|---|
| 操作逻辑 | **中** | 状态机（智能/手工）、写入闸门、二次确认的设计是自洽的；但「能力承诺」没有随权限闸门降级，形成同页自相矛盾 |
| 页面布局 | **中偏低** | 概览页信息架构清晰；4 个页面缺滚动容器导致长内容不可达，手工微调页头部文字与按钮重叠 |
| 悬浮提示准确性 | **两极分化** | 8 张指标卡的口径说明写得非常严谨、可直接当范例；但「置灰按钮看原因」在 WPF 下根本弹不出来，且绑定的原因文案指向已退役的驱动 |

**最优先 3 件事**（均为低成本、高收益）：
1. 给置灰按钮补 `ToolTipService.ShowOnDisabled="True"`，否则「悬停可看原因」是空承诺（UX-01）。
2. 把 `SessionState.cs` 残留的 WinRing0 / 0.9.4 文案统一改成 PawnIO / 0.9.6+（UX-02）。
3. 给 `MainWindow.Host` 或各页根加 `ScrollViewer`，让诊断页底部内容可达（UX-03）。

问题统计：P0 = 4、P1 = 7、P2 = 7，共 18 项。

## 三、逐页评估

### 3.1 概览页（`overview.png`）

| 维度 | 评估 |
|---|---|
| 操作逻辑 | 8 张卡 + 统一时序图 + 决策凭证 + 决策流水 + 底部控制条，信息层级合理。「停止监控 / 施加压测负载 / 负载场景 / 采样间隔 / 导出 CSV」集中在一行，主流程 1 步可达。**不足**：「停止监控」是状态切换按钮却用绿色主按钮，且未勾选压测时「负载场景」下拉仍可操作，操作结果预期不清。 |
| 页面布局 | 4×2 卡片网格整齐；副标题普遍用 `TextTrimming="CharacterEllipsis"` 后**被截断**（CPU 负载、GPU 负载、风扇），完整口径只能靠整卡 ToolTip 补偿。决策流水理由列换行后被滚动区裁切。 |
| 悬浮提示 | **本页质量最高**：CPU 负载（GetSystemTimes 与任务管理器口径差异）、GPU（NVAPI GPU Core vs PDH GPU Engine）、显存（专用 vs 专用+共享）、风扇（EC 原始字节/非 RPM/不拿演算值冒充实测）四段说明准确且可复算。**问题**：提示挂在整张卡 `Border` 上，300 字长文在卡片任意位置触发、不可复制；`决策 PL1` 卡副标题「默认功率 -- W（实读 PL1）」值为空却标「实读」（UX-14）；图表说明「温度接近上限时才出现虚线」与代码条件不符（UX-08）。 |

### 3.2 智能微调页（`tuning.png`）

| 维度 | 评估 |
|---|---|

| 悬浮提示 | 「开始两段式标定」置灰 + ToolTip 绑定 `CalibrationBlockedReason`，但禁用控件不弹提示（UX-01），且该文案仍是 WinRing0 / 0.9.4（UX-02）；右列「Tau / EPP / 风扇…从不写入硬件」是全局断言，与手工页可写 Tau/EPP/电压相矛盾（UX-07）；「风扇由 EC 自动调速」在风扇读数 N/A、EC 字节语义未确认的前提下属未验证断言（UX-11）。 |

数值复核（可作为文案改进的验收锚点）：轻载基线 45.2°C @ 5.4W、Rth 0.79 K/W → 45.2 + (52 − 5.4) × 0.79 = **82.0°C**，与「预测稳态 82.0°C / 按 52W 外推」一致；但同一卡片又写「决策 PL1 上限 60W」，60W 对应约 **88.3°C > 88°C 天花板**。两个数值并列且未各自标注功耗基准，极易被读成「60W 已通过热校验」（UX-10）。

## 六、优先级排序与风险登记

**MoSCoW 收口**：

- **Should（下一版）**：UX-08 ~ UX-11。涉及数值口径与图表可读性，需配合一次实机复核。

## 七、值得保持的设计（避免优化时误伤）

1. **8 张指标卡的口径说明**是全产品质量最高的文案：明确区分系统计时 CPU 负载、NVAPI GPU Core、专用显存、EC 档位非 RPM，并主动声明「不拿演算值冒充实测」。建议作为文案规范沉淀。
2. **三层参数模型表述准确**：设置页「固件 PL1/PL2 出厂默认、掉电即恢复、无法持久化；可持久化的是软件侧标定与手动微调，开机由软件重放」——与产品模型完全一致，勿改。
3. **数值可交叉复核**：60.9°C + 27.1°C 余量 = 88°C 天花板；45.2 + (52 − 5.4) × 0.79 = 82.0°C。决策凭证给出规则名与评估路径，可追溯。
4. **危险操作防护完整**：二次确认、启动备份、回读校验、失败回滚、退出恢复、开机重放，且写入闸门在状态条 / 底栏 / 页脚三处一致呈现。
