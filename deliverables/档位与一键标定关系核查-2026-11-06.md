# 档位选择与一键标定：关系与有效性核查（2026-11-06）

## 一句话

**档位 = 用户意图（决定决策树怎么算）**，**一键标定 = 测这台机器的热阻（决定算得准不准）**。
标定结束给出「推荐档位」，档位的温度天花板又反过来决定标定的推荐 PL1。
**两者都不直接写寄存器**；写入只发生在自动接管四个闸门全开时，且只写 `0x610` 的 PL1 / PL2。

## 两者关系

| | 一键标定 | 档位（静音 / 均衡 / 性能） |
| :--- | :--- | :--- |
| 输入 | 轻载基线 12s + 全核 SIMD/FMA 升温 + 稳态 10s 的实测温度/功耗 | 用户点击卡片 |
| 产出 | `Rth`、轻载基线 `(IdleC, IdleW)`、预测稳态、推荐档位、推荐 PL1 | `CeilingC`(85/88/92°C) + `EPP`(200/128/0) + `Pl2Ratio`(1.15/1.25/1.35) + `TauSeconds`(8/16/32) + `FanMaxPercent`(55/75/100) |
| 落盘 | `Settings.Calibration`（L2 智能标定推荐） | `Settings.Profile` + `Settings.CeilingC` |
| 写 MSR | **否**（弹窗明确写「不会写入 MSR」） | **否**（由自动接管闸门决定） |

链路：

```
BeginCalibration → 三段采样 → ThermalCalibration.TryTwoPoint(Rth)
  → _controller.ApplyCalibratedRth(Rth)                 [决策前馈立即生效]
  → SaveCalibrationSnapshot
      · 用当前 CeilingC 反解 MaxPowerForCeiling → RecommendedPl1W   ← 档位影响标定
      · 按预测稳态温度给 Recommended 档位
      · 记录 VoltageContextMv；不覆盖 L3 用户编辑值
  → CalibrationFinished → TuningPage 弹确认框
  → 用户点「应用推荐档位」→ SetProfile(Recommended)
      · 改 Profile 与 CeilingC，不碰寄存器                          ← 标定影响档位
```

反向耦合：标定得到的 `Rth` 经 `SetThermalBaseline` 进入 `AutoCpuController`，
每拍用 `MaxPowerForCeiling(Rth, IdleC, IdleW, CeilingC)` 钳制决策 PL1 上限
（`AutoCpuController.cs:148`），所以**同一档位在标定前后给出的 PL1 上限不同**。

重新标定只更新 L2，绝不覆盖 L3 手动微调值。

## 有效性核查结论

### 算法层：有效，且有 A/B 断言守护

`SetProfile` → `Profile` → `_controller.Update(profile: Profile)` → `UserProfile.FromName` →
五个决策树节点读 `TargetTemperatureCeiling / Pl2Ratio / TauSeconds / Epp / FanMaxPercent`。
新增 `ProfileEffectTests`：同一物理状态下仅换档位，输出 `EPP 200/128/0`、`Tau 8/16/32s`、
`PL2 51.75/56.25/60.75W` 全部不同；轻载时 PL1 一律锚定固件实读 45W（不抬功耗墙）。
另验证 `Update` 用调用方 `ceilingC` **覆盖**档位自带天花板——这是自定义天花板与标定推荐能生效的前提。

### 寄存器层：多数参数永远不落地

`TryAutoApply` 只调 `MsrGuard.Apply(pl1, pl2, tau, writeTimeWindow: false)`：

| 参数 | 决策树使用 | 是否写入硬件 |
| :--- | :---: | :--- |
| PL1（主输出） | ✅ | ✅ 仅四闸门全开 |
| PL2 | ✅ | ✅ 仅四闸门全开 |
| `CeilingC` | ✅ 触发触顶降功耗、钳制上限 | 不适用（软件阈值） |
| `TauSeconds` | ✅ | ❌ `writeTimeWindow:false` → `MsrGuard.Apply` 用 `before.TauS` |
| `Epp` | ✅ 决策凭证显示 | ❌ 自动链路从不调 `ApplyEpp` / `ApplyHwp` |
| `FanMaxPercent` | ✅ 演算建议值 | ❌ 软件不写 EC / PWM |

**四个闸门**（`SessionState.AutoApplyAllowed`）：
`!_manualLock`（无 L3 手动微调）∧ `MsrWritable`（管理员 + 驱动）∧ `AllowRealWrite` ∧ `AutoTakeover`。
本机 `settings.json` 有 `Manual`（PL1 45W / PL2 56.2W / Tau 32s / EPP 60 / MaxPerf 36），
开机重放时置 `_manualLock = true` → **当前状态下切换档位只改演算值，一个字节都不写**。
界面底栏与概览说明此前只看 `AllowRealWrite && MsrWritable`，管理员 + L3 锁时会误报「写入已授权」，已修正。

### 发现并修复的真 bug：档位重启丢一半

`SessionState._profile` 字段硬编码 `= "balanced"`，构造函数**只恢复了 `CeilingC`，没恢复 `Settings.Profile`**：

- 用户选「静音优先」→ 当次会话正确，`settings.json` 存 `Profile=silent / CeilingC=85`；
- 重启 → `_profile` 回到 `balanced`，天花板仍是 85 → 界面显示「档位 均衡 · 天花板 85°C」，
  档位单选按钮错选「均衡」，**决策树拿到的是均衡的 EPP 128 / Tau 16s / PL2 1.25**，
  而不是用户要的静音 200 / 8s / 1.15。

证据：`deliverables/UI-概览-2026-11-06.png`（修复前，Tau 16s / EPP 128）与
`UI-概览-修复后-2026-11-06.png`（修复后，Tau 8s / EPP 200、底栏「静音优先」）。

修复：构造函数从 `Settings.Profile` 恢复并规范化非法值；`--smoke` 增加
「档位持久化 已正确恢复」断言与 `自动写入闸门` 一行输出（不进 UI，避免堆说明文字）。

## 口径修正（不新增 UI 行数）

- `FooterMode` / `MonitorHintText` 纳入 `_manualLock` 与 `AutoTakeover`，不再把「可写」说成「已在写」；
- 智能调优页天花板说明补「切换档位会重置为该档预设值」（`SetProfile` 确实会覆盖自定义天花板）；
- 「当前决策参数」底部说明改为「Tau / EPP / 风扇为演算值，未写入硬件；自动接管开启时仅 PL1 / PL2 写入 0x610」。

## 用户怎么自己验证

1. 管理员运行 `ThermalTuner.App.exe --smoke`，看「档位持久化」「自动写入闸门」两行。
2. 智能调优页切换三档 → 「当前决策参数」的 Tau / EPP / PL2 应立即变化；天花板随之重置。
3. 退出重开程序 → 档位保持上次选择（本次修复点）。
4. 一键标定 → 弹窗给推荐档位 → 点「应用推荐档位」→ 档位与天花板改变，寄存器不变。
5. 若确实要让档位影响硬件：设置页**清除保存的微调参数** → 开启自动接管 → 管理员 + 允许写入 MSR；
   此时仅 PL1 / PL2 会写入 `0x610`。回滚：点「恢复原值」或直接重启（MSR 易失）。
