## 2. 测试分层与方法

| 层级 | 范围 | 是否接触硬件 | 入口 |
| :--- | :--- | :--- | :--- |
| 单元 / 功能 | Core 纯逻辑：编解码、热模型、决策树、平台推导、参数防呆 | 否 | `dotnet run --project tests/ThermalPilot.Core.Tests` |
| 组件 / 界面 | App 会话初始化、六页 XAML 加载与布局、MSR 通道只读探测 | 只读 | `ThermalPilot.App.exe --smoke` / `--msr-probe` |
| 集成 | 构建 → 测试 → Runner → 发布 → 冒烟 → 通道 → 监控 → 压测 | 部分 | `build/test.ps1` |
| 硬件在环 | 真实写入 0x610 / 0x1AD，满载测温度/功耗/频率 | 是（需管理员） | `--write-test` / `--stress-test` / `--calibrate-sweep` / `--turbo-stress` |

设计原则：**能在无硬件环境验证的逻辑全部前置到功能测试**；硬件在环只验证「真写入是否生效、能否恢复」，避免把硬件状态当作测试前提。

## 5. 硬件在环实测数据

### 5.1 写入链路（`--write-test` / `--turbo-probe`）

| 对象 | 操作 | 回读结果 | 恢复 |
| :--- | :--- | :--- | :--- |
| 0x610 | 同值写回 → 改 PL1 → 回读 | 与目标一致 | 45.0W / 56.2W / 28672s |
| 0x1AD | 拉平 38x | `0x26262626`（38/38/38/38） | `0x22232426`（38/36/35/34） |
| 0x774 EPP | 写入 → 回读 | 一致 | 恢复启动备份 |

### 5.2 A/B/C 满载压测（`--stress-test --seconds 20 --low-pl1 15`）

| 阶段 | 0x610 实读 PL1 | 稳态均温 | 均包功耗 | 均核频 |
| :--- | ---: | ---: | ---: | ---: |
| IDLE（空载） | 45.0 W | 59.7 °C | 19.21 W | 3.47 GHz |
| LOAD_FW（固件默认） | 45.0 W | 68.3 °C | 33.41 W | 3.41 GHz |
| LOAD_LOW（降墙） | **15.0 W** | **55.2 °C** | **14.96 W** | **2.23 GHz** |
| LOAD_HIGH（放宽） | 65.0 W | 68.5 °C | 33.23 W | 3.41 GHz |

- 降墙段：**ΔT −13.09°C / ΔP −18.45W / Δf −1.18GHz**，参数写入生效的直接证据。
- 放宽段：寄存器确实变成 65W，但实际功耗 33.2W 远低于墙，温度与频率无变化 → 调高天花板物理等价。
- 本机满载峰值 33.9W，仅为固件 PL1 45W 的 **75%**，这是「往上调没有感受」的根因。
- 收尾已恢复固件默认，未留残留。

### 5.3 阶梯智能标定（`--calibrate-sweep --seconds 15 --ceiling 85`）

| 档位 | 目标 PL1 | 实读 PL1 | 实测功耗 | 稳态温度 | 均频 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| 1 | 45.0 W | 45.0 W | 33.29 W | 68.4 °C | 3.41 GHz |
| 2 | 36.0 W | 36.0 W | 33.42 W | 68.9 °C | 3.41 GHz |
| 3 | 27.0 W | 27.0 W | 26.96 W | 64.6 °C | 3.13 GHz |
| 4 | 20.2 W | 20.2 W | 20.21 W | 59.9 °C | 2.82 GHz |
| 5 | 15.8 W | 15.8 W | 15.71 W | 55.6 °C | 2.33 GHz |

拟合 `T = 44.85 + 0.719·P`，R² = **0.994**；反解 85°C 上限 → 可持续功耗 55.9W，推荐 PL1 **45.0W（即固件默认值）**。
说明本机散热余量充足，智能标定算出的最优解就是「不需要降墙」——产品定位应是温控/静音，而非性能释放。

### 5.4 睿频 A/B（`--turbo-stress --seconds 20`）

| 指标 | 出厂倍率表 | 拉平 38x | Δ |
| :--- | ---: | ---: | ---: |
| 单线程核频 | 3.44 GHz | 3.44 GHz | 0.00 |
| 均核频（6 线程） | 3.41 GHz | 3.41 GHz | −0.00 |
| 均包功耗 | 32.76 W | 32.68 W | −0.08 W |
| 均温度 | 67.5 °C | 69.0 °C | +1.50 °C |

0x1AD 全程实读 38/38/38/38，但 PCU 未按新表提高全核频率 → **「值可写」≠「硬件采纳」**，38x 无性能收益。

## 6. 测试发现与修复

| # | 缺陷 | 影响 | 修复 |
| ---: | :--- | :--- | :--- |
| 1 | 仓库只有 `.slnx`，本机 .NET SDK 8.0.427 无法解析（MSB4068） | README 的一键构建命令不可用，CI 无法构建 | 生成经典 `ThermalTuner.sln`（5 项目），删除 `.slnx`；`dotnet build` 根目录直接通过 |
| 2 | `--turbo-probe` 把「当前 0x1AD」当出厂值；开机重放 36x 后恢复成真出厂 38x，比对失败；且目标值等于当前值时跳过写入仍判失败 | 自检假阴性，误报硬件异常 | 以 `StartupTurboBackup` 为出厂基准；当前已等于目标时先写探针档（36x）确保真实走一次写入→回读；最终比对出厂备份。复测 PASS |
| 3 | `StressProbe` 结论文案仍写「0x1AD / 0x150 暂未接入」 | 报告与 v0.4.3 代码事实矛盾 | 改为「0x1AD 已接入；0x150 尚未接入」 |
| 4 | 集成脚本三处 PowerShell 5.1 兼容问题：`Start-Process` 遇 `HTTPS_PROXY`/`https_proxy` 重复键抛异常；原生 UTF-8 输出按 OEM 解码成乱码；提权进程句柄不可等待 | 脚本在本机直接失败或提前退出 | 改用 .NET `Process` 启动（不重建环境字典）、异步读流按 UTF-8 解码、提权分支轮询报告文件；复跑 15/15 PASS |

> 第 2 条是本次测试最有价值的产出：如果不修，用户只要保存过睿频微调，`--turbo-probe` 就会稳定报 FAIL，把正常状态误判为硬件故障。

## 7. 残留风险与建议

| 风险 | 说明 | 建议 |
| :--- | :--- | :--- |
| WinRing0 被拦截 | 老式未签名内核驱动，部分机器 HVCI / Defender 会阻止 | 首次运行做无害写探测并在界面标注「只读演练 / 已生效」 |
| 机型差异 | 部分平台 `0x774` / `0x1AD` 不可读，相关命令会 SKIP | 保持当前「读不到就禁用写入与持久化」策略 |
| 压测有副作用 | 满载写入会真实改变功耗墙、风扇转速上升 | 仅在受控机器执行 `-Full`；结束必须核对收尾恢复 |
| 测试框架自研 | 无 xUnit 报告、无覆盖率统计 | 后续可迁移 xUnit + coverlet；当前零依赖入口便于落地机复跑 |
| 未覆盖 UI 交互 | `--smoke` 只验证加载与布局，不覆盖点击/输入 | 关键路径（应用参数、恢复原值、标定按钮）建议补 UI 自动化或人工清单 |

## 8. 复跑方式

```powershell
# 功能测试（无需硬件）
dotnet run --project tests/ThermalPilot.Core.Tests -c Release

# 轻量集成（非管理员）
powershell -ExecutionPolicy Bypass -File build/test.ps1

# 完整集成（管理员 + 三轮压测，约 5 分钟）
powershell -ExecutionPolicy Bypass -File build/test.ps1 -Hardware -Full -Elevate
```
