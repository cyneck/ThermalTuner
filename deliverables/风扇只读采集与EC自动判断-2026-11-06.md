# 风扇运行百分比接入与 EC 自动判断（2026-11-06）

## 一句话结论

`nbfc.exe status` 报告的 `Current fan speed 88.83%` **是真实 EC 读数**，不是静态占位：
`ec-probe read 149` 得到 `80 (0x50)`，按生效配置 `Min=255 / Max=58` 换算正好 `88.83%`；
`ec-probe dump` 里偏移 `0x95`(=149) 也是 `0x50`，交叉验证一致。
因此已把「风扇运行百分比」接入实时监控的指标卡、采样明细与 CSV，全程**只读、不写 EC**。

## 自动判断链路（不硬编码寄存器）

新增 `Services/EcFanReader.cs` + `--ec-probe` 命令，启动时/手动执行时自动完成：

1. 自动定位 NBFC 安装目录（`nbfc.exe` + `ec-probe.exe` 同时存在才算可用）；
2. 读 `nbfc.exe status` → 取 `Selected config name`（当前 `HP OMEN Notebook PC 15`）；
3. 在 `Configs\<name>.xml` 解析 `ReadRegister=149`、`WriteRegister=148`、`MinSpeedValue=255`、
   `MaxSpeedValue=58`、`EcPollInterval=2222ms`、`FanDisplayName`；
4. 提权时用 `ec-probe read <ReadRegister>` 取 EC 原始值；
5. 用 `FanPercentCodec.FromRaw(raw, min, max)` 换算成运行百分比（反向编码同样成立）；
6. 用 `ec-probe dump` 全量快照交叉验证、`ec-probe monitor -t 6 -d -r` 列出变化寄存器，
   并连续 6 次采样判断读数是否活跃。

**命令边界**：只调用 `read / dump / monitor`，**绝不调用 `ec-probe write`**。
`ec-probe` 加载 EC 插件需要管理员；普通权限下明确记录失败原因。

## 运行时采集（低频、只读、有回退）

`HardwareTelemetry.WithExtras()` 的风扇优先级：

| 顺序 | 来源 | 条件 | 副标题显示 |
| :--- | :--- | :--- | :--- |
| 1 | LHM `SensorType.Fan` / `Control` | 原生传感器可读 | `LHM 实测 · 只读` |
| 2 | **EC 直读**：`ec-probe read` + 配置换算 | 管理员 + NBFC 已装 | `EC 直读 · 只读` |
| 3 | `nbfc.exe status` 已换算值 | 普通权限也可 | `NBFC 服务 · 只读` |
| 4 | N/A | 以上都不可用 | `无可用风扇读数` |

每 **2.2 秒**最多刷新一次（与 NBFC 的 `EcPollInterval` 对齐），避免每拍启动外部进程；
普通权限下 EC 直读失败会在本进程内标记不可用，不再反复尝试（提权重启后自动复位）。
任何一级失败都不影响温度 / 功耗 / 决策树主链路。

## 关于「读数恒定」与配置匹配

6 次 / 20 秒观察里 `88.83` 恒定，而温度 44→62→44°C 波动。原因：NBFC 当前
`Read-only=True`、`Target=0.00`，不写 EC；风扇由 EC/BIOS 自身策略固定在该档。
这是**真实但当前不变化**的读数，不是假数据。

`HP OMEN Notebook PC 15.xml` 的 `NotebookModel` 是 `HP OMEN 5001NG`，本机主板为 `HP 838F`。
寄存器 149 的读数能被 dump 与换算双重印证，说明**读路径映射正确**；但配置是否完全匹配
（尤其写路径 148 与 `RegisterWriteConfigurations` 的初始化写入）**尚未验证**，本轮不写 EC。

## 后期「风扇微调」的边界（本轮不实现）

当前实现的只是**采集层**。要做控制层需单独设计并显式授权，至少处理：

- 写 `WriteRegister=148`，按 Min/Max 反算原始值，范围钳在 `[MinSpeedValue, MaxSpeedValue]`；
- `ResetRequired` / `FanSpeedResetValue=89` 与 `RegisterWriteConfigurations`（初始化写 147=20、复位 4）；
- **与 NBFC 服务抢 EC**：两者同时写会互相覆盖，必须明确谁接管，或要求先停 NBFC 服务；
- 写入前备份、回读校验、失败回滚、退出恢复原值、二次确认（写错 EC 寄存器有硬件风险）；
- 与决策树 `TargetFanPercent` 的关系：是否允许自动接管驱动真实风扇，还是仅供手动微调。

`EcFanReader.Definition()` 已把 Read/Write/Min/Max/轮询间隔暴露出来，控制层可直接复用，
不需要重新解析配置。
