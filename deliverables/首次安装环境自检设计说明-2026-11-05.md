## 一、结论

1. **已实现**：软件在**第一次安装启动后自动跑一次只读环境自检**，逐项确认哪些参数能获取；
   自检结论落盘 `%LOCALAPPDATA%\ThermalPilot\capability.json`，高级参数页据此**自动禁用不可编辑项**，
   并在页面顶部显示「能力摘要 / 禁用结论 / 外部依赖处置建议」。
2. **已实现依赖提示**：LHM 版本不对、驱动未加载、缺管理员、HVCI 拦截、虚拟化、只读通道
   都会给出具体处置动作（安装/回退哪个包、去哪里开权限）。
3. **⚠️ 必须纠偏**：**PawnIO 不是要提示安装的依赖，恰恰是要避免的**。
   LHM 0.9.6+ 换成 PawnIO 后，随包 IntelMSR 模块只有 `ioctl_read_msr`（只读），
   会让 `0x610` 写入能力静默消失。项目固定 0.9.4 / WinRing0；
   自检检测到 PawnIO 后端或缺少 `Ring0.WriteMsr` 时会**告警并提示回退 0.9.4**，不会建议安装它。
4. **已编译新的可执行体验包**（Release / win-x64 / 自包含单文件），冒烟与环境自检均通过。

## 二、自检检查什么

| 类别 | 检查项 | 判定方式 |
| :--- | :--- | :--- |
| 外部依赖 | `LibreHardwareMonitorLib` 程序集版本 | `Assembly.GetName().Version`，必须为 0.9.4 |
| 外部依赖 | MSR 后端 / `Ring0.WriteMsr` 是否存在 | `MsrChannel.BackendName` + 反射方法列表 |
| 权限 / 环境 | 管理员、HVCI 内存完整性、虚拟化 | WindowsPrincipal / WMI `Win32_DeviceGuard` / `HardwareProbe` |
| 通道 | `MsrStatus`（Writable / ReadOnly / NoAdmin / ModuleUnavailable / DriverUnavailable / NotInstalled） | `MsrChannel.Open()` |
| 参数项可读 | `0x610`、`0x774`、`0x1AD`、`0x150`、`0x606`、`0x611` | 逐寄存器 `TryRead` |
| 参数项可读 | 温度 / 实测功耗 | 采一拍遥测（`TempReadable` / `PowerMeasured`） |
| 参数项可写 | 0x610 / 0x774 / 0x1AD / 0x150 | **仅管理员**下做无害探测：同值写回、`−10 mV` 后强制回零 |
| CPU 能力 | 厂商 / 代际 / 移动版 / 是否 K | `CpuCapability.Probe`，**只作提示，不承诺能力** |

### 依赖处置建议（按状态触发）

| 状态 | 提示动作 |
| :--- | :--- |
| LHM 版本 ≠ 0.9.4 | 安装 / 回退 NuGet 包 `LibreHardwareMonitorLib 0.9.4`，确认随包带 WinRing0 驱动 |
| PawnIO 后端 / 无 `WriteMsr` | **不要装 PawnIO**，回退 0.9.4 / WinRing0（说明只读后果） |
| `NoAdmin` | 点界面「以管理员重启」 |
| 驱动未加载 / 不可用 | 管理员运行；检查 HVCI、Defender、第三方安全软件白名单 |
| `ModuleUnavailable` | LHM 程序集缺 Ring0 接口，安装 0.9.4 |
| `ReadOnly` | 固件锁或后端无写接口，参数只能查看 |
| 通用 | 框架依赖版需 .NET 8 桌面运行时；自包含版免装（推荐） |

## 三、UI 禁用规则（简单，不新增页面）

- 判定依据是「**能否获取**」+「**实测是否可写**」，不是型号猜的：`0x610` 不可读 → 禁用 PL1/PL2/Tau；
  `0x774` 不可读 → 禁用 EPP / MinPerf / MaxPerf / ActivityWindow；`0x1AD` 不可读 → 禁用睿频；
  `0x150` 不可读或 `--voltage-probe` 实测不可写 → 禁用电压。
- **能否真实写入**仍由既有的「管理员 + 允许写入 MSR」双开关决定，走演练模式；
  普通权限下不会把所有项判死，用户提权重启后禁用清单会自动刷新。
- 高级参数页顶部新增一个紧凑卡片：能力摘要 + 禁用结论 + 依赖建议（全文作 ToolTip）
  + 「重新自检（管理员，含写入探测）」按钮。**没有新增页面、没有新增对话框层级**。

### 启动流程（三层）

| 场景 | 行为 |
| :--- | :--- |
| **首次安装启动（UI）** | 自动跑只读自检 → 落盘 `capability.json` → 弹一条「首次环境自检」告警（含依赖提示）→ 置 `EnvironmentChecked=true` |
| 每次后续启动 | 静默刷新只读自检（提权状态变了，禁用清单跟着变），不重复弹窗 |
| 命令行（`--smoke` / `--env-check`） | 可以跑自检并落盘，但**不消耗首次标记**，保证用户第一次双击仍能看到提示 |
| 管理员手动「重新自检」/ `--env-check` | 补做无害写入探测，刷新可写性结论 |

## 五、体验包与一步步验证

**包位置**

- 目录（**以此为准**）：`dist/ThermalPilot-v0.4.3-2026-11-05-r2/ThermalPilot.App.exe`（157.34 MB 自包含单文件，免装 .NET 8）
- 压缩包：`dist/ThermalPilot-v0.4.3-2026-11-05-r2-win-x64.zip`（63.79 MB）
- 不带 `-r2` 的目录及两个旧 zip 是历史产物：旧 exe 被运行中的托盘占用无法覆盖，
  且安全策略不允许递归删除，故保留。**体验请用 `-r2`**。
- `dist/` 已在 `.gitignore` 排除，不入库；新目录避免覆盖被托盘占用的旧 `dist/ThermalPilot`。

**建议按顺序**

1. **普通权限双击** `ThermalPilot.App.exe` → 看「诊断与日志」里的「首次环境自检」告警，
   以及高级参数页顶部卡片：应显示 `NoAdmin`、依赖建议「点以管理员重启」、Voltage 禁用。
2. 点界面「以管理员重启」（UAC 点是）→ 重启后禁用清单自动刷新，Voltage 仍禁用（本机实测不可写）。
3. 高级参数页点「重新自检（管理员，含写入探测）」→ 摘要变为「写入能力已实测」，
   检查各参数项的可写性结论。
4. 想看完整报告：管理员命令行跑
   `ThermalPilot.App.exe --env-check --out env-check.txt`，或看 `deliverables/env-check-release-2026-11-05.txt`。
5. 确认禁用项符合预期后，再试 EPP 128 / Max Perf 34 等编辑（注意：本机 `0x774` 会在 250ms 内被系统覆盖，
   详见 `核心高级参数覆盖盘点与实施计划-2026-11-05.md` §9.2）。

**回滚**：删掉 `%LOCALAPPDATA%\ThermalPilot\capability.json` 即恢复「未自检」状态；
把 `settings.json` 的 `EnvironmentChecked` 改回 `false` 可重看首次提示；
旧版 `dist/ThermalPilot` 未被改动，随时可回退。
