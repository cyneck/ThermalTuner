# 固件基准口径与一次性验证清单

生成时间：2026-11-05 18:35　范围：Tau（0x610）/ EPP（0x774）的固件层可改性、当前值合理性、是否需要一次性写入

---

## 一、结论（先说结果）

1. **Tau / EPP 不是「固件层不能改」，而是「寄存器可写、但写入不持久」。**
   `0x610`、`0x774` 都是易失 MSR：CPU 上电时由 BIOS/固件按出厂策略初始化，软件写的是**本次上电期间的当前值**，
   重启/断电后固件重新加载默认值。要持久改变出厂策略，只能改 BIOS/NVRAM 设置——本机 OEM BIOS 是否暴露
   该选项**待核实**，且刷写/改 NVRAM 风险高，不属于本软件范围。

2. **当前固件值没有不合理，因此本次不写入任何「更合理的固件基准」。**
   - Tau = 28672 s 是 Intel SDM 合法编码 `(1+3/4)·2^14`（X=14, Y=3），不是解码 bug，也不是错误值；
     它是 OEM 让 PL1 只约束「长期平均功率」、短时爆发交给 PL2 的策略选择。
   - EPP = 0（性能优先）在规格 `[0,255]` 内，且出厂备份与当前实读**完全一致**，软件重放的 `Epp=0` 是空操作。
   - 对「短时温控压测」而言，8 小时窗口确实不友好，但这属于**调参目标**问题，不是固件缺陷；
     正确做法是把秒级 Tau / 平衡 EPP 作为**软件侧重放值**，现状已经这么做了（Tau 16 s）。

3. **真正需要处理的是「现场基准不干净」**：软件正在运行，开机重放把 Tau 从 28672 s 改成 16 s，
   导致今天所有压测都跑在「软件微调态」，不能代表固件默认行为。这个可修，但方向是**恢复**，
   不是「写入一个新基准」。

> ⚠️ 「单次写入一个合理数值作为固件基准」这个动作在技术上不成立，本次**未执行**：
> 写 MSR 改不了固件基准（重启即失效）；改 `msr-startup.json` 只会伪造出厂基线，
> 让 `Restore()`、偏离判断、恢复逻辑全部失真。详见第四节。

## 三、合理性判定（逐项）

| 项 | 判定 | 依据 / 影响 |
| :--- | :--- | :--- |
| Tau 28672 s | **合法、非缺陷** | 合法编码，OEM 散热策略；短时压测看不到 PL1 钳制，但日常允许睿频爆发 |
| PL1 45 W / PL2 56.25 W | **合理** | i7-7700HQ 标称 45 W TDP；场景扫描实测重载峰值 43.93~44.89 W，正好贴墙 |
| EPP 0 | **规格内，但偏性能** | 不利于静音/温控目标；若想改善，改成 128（平衡）即可，属软件侧调参 |
| 当前 Tau 16 s | **合理（软件微调态）** | 由用户保存的微调值重放，短窗口让 45 W 墙在 8 s 压测内真实钳制 |

**结论：没有需要「修正」的固件值。** 若用户认为 28672 s 太长，正确落点是 `settings.json` 的 `Manual.TauS`
（已经是 16），不是固件。

## 四、为什么「单次写入作为固件基准」不成立

| # | 理由 | 代码位置 |
| :--- | :--- | :--- |
| 1 | `0x610/0x774` 是易失寄存器，写入只在本次上电有效；重启后 BIOS 重新初始化，基准仍是 45 W / 28672 s / EPP 0 | `src/ThermalTuner.Core/Msr/RaplPowerLimit.cs:40`、`MsrGuard.cs:451` |
| 2 | `msr-startup.json` 是软件侧「首次启动快照」，不是固件里的常量；改它等于伪造基线，`Restore()` 会把机器恢复成一个假出厂值 | `MsrGuard.cs:105-117`、`:451-481` |
| 3 | 现有「恢复原值」已经是「单次写回固件出厂值」的正确实现：整字写回启动备份 + 回读校验 + 审计，含 EPP 与睿频表 | `SessionState.cs:952-963`、`MainWindow.xaml.cs:130-138` |
| 4 | 软件退出即恢复（`RestoreOnExit=true`），根本不需要额外写入 | `SettingsStore.cs:14`、`MainWindow.xaml.cs:132` |

> 如果用户要的是「本次运行期间用一个特定值当基准」，那叫**运行值**，不叫固件基准；
> 用高级参数页或 `--stress-test` 临时写入即可，重启自动失效。

## 七、A 方案：一步步验证（每步都有可判定预期）

> 全程用 `D:\code\ThermalTuner\src\ThermalTuner.App\bin\Debug\net8.0-windows\ThermalTuner.App.exe`。
> `dist/` 里的可执行文件仍是旧版，**不要用**。

**Step 0 — 退出托盘程序（你做）**
右下角托盘图标 → 退出（不是关窗口，`CloseToTray=true`）。
预期：`RestoreOnExit=true` 触发 `RestoreOriginal()`，`0x610` 整字回到 `0x004281C200DD8168`。
注意：若托盘程序不是以管理员启动（`MsrWritable=false`），退出恢复不会触发——不影响结果，
Step 2 重启后 BIOS 仍会重新加载固件默认值；`RunAtStartup=false` 已确认不会自启。

**Step 1 — 临时关闭开机重放（你做，二选一）**
- 界面：设置页取消勾选「开机重放微调参数」；
- 或直接编辑 `%LOCALAPPDATA%\ThermalTuner\settings.json`，把 `"ReplayOnStartup": true` 改成 `false`
  （**先备份该文件**：`copy settings.json settings.json.bak`）。

**Step 2 — 重启机器（你做）**
这一步是「固件值不可持久修改」的最强证据：重启后 BIOS 重新初始化 MSR。

**Step 3 — 只读实读（你做，点 UAC）**
用**管理员 PowerShell**执行：

```powershell
& 'D:\code\ThermalTuner\src\ThermalTuner.App\bin\Debug\net8.0-windows\ThermalTuner.App.exe' `
  --msr-probe --out 'D:\code\ThermalTuner\deliverables\msr-probe-firmware-default.txt'
```

可判定预期（三项全中才算「干净固件基准」）：
- `0x610 原始 : 0x004281C200DD8168`
- `Tau : 28672 s`，`PL1 45.000 W`，`PL2 56.250 W`
- `0x774 : 0x0000019E0000261C`（EPP 0）

若 Tau 仍是 16 s → 说明软件还在跑或重放没关，回 Step 0/1 重来。

**Step 4 — 固件默认态场景扫描（你做，点 UAC）**

```powershell
& 'D:\code\ThermalTuner\src\ThermalTuner.App\bin\Debug\net8.0-windows\ThermalTuner.App.exe' `
  --scenario-sweep --out 'D:\code\ThermalTuner\deliverables\scenario-sweep-firmware-default.txt' `
  --csv 'D:\code\ThermalTuner\deliverables\scenario-sweep-firmware-default.csv' `
  --seconds 8 --target-ratio 0.9
```

判定口径（**以下为待实测的假设，不是已得结论**）：
- 长 Tau 下短时 8 s 压测可能不受 PL1 45 W 钳制，SIMD_FULL 峰值可能**高于 45 W**（受 PL2 56.25 W 短时窗口约束）；
- 若峰值仍 ≈45 W，说明本机 PL1 在短时也在钳制；
- 与 `scenario-sweep-admin-2026-11-05.txt`（重放态，43.93 W / 98%）对比，差值即「软件微调 Tau」带来的真实收益。

**Step 5 — 恢复现场（你做）**
把 `ReplayOnStartup` 改回 `true`（或恢复备份的 settings.json），重新启动程序即可回到现有微调态。

## 九、假设与待核实（不编造）

- **假设**：`msr-startup.json`（11-03 15:51 采集）确实是机器冷启动、软件未重放时的固件默认。
  若当时已有重放，备份会偏。**待核实**：Step 2 重启后的 Step 3 实读值与之比对即可确认。
- **待核实**：本机 OEM BIOS 是否暴露可持久化的 PL1 / Tau / EPP 选项（本软件不探测、不修改 BIOS）。
- **待核实**：`0x774` 可能被 Windows 电源计划 / Intel DTT 周期性改写，EPP 的稳定性弱于 `0x610`；
  本轮单次实读一致不能证明「永不被改写」。
- **口径**：Intel SDM 允许 Tau 编码 `X∈[0,31] / Y∈[0,3]`，28672 s 合法；
  「常见 OEM 取秒级」是经验判断，未引用具体厂商文档，不作为量化依据。
