== 2. 软件到底会动哪些参数（代码事实）==
· 写 MSR 0x610（PKG_POWER_LIMIT）：PL1 长时功耗墙 / PL2 短时爆发墙 / Tau 平均窗口。唯一真实写入目标。
· 写 MSR 0x774 [31:24]：HWP EPP 能效偏好。本机 0x774 不可读，代码已禁用写入与持久化。
· 只读 MSR 0x606 / 0x611（或 AMD 0xC0010299 / 0xC001029B）：RAPL 能量单位与能量计数器，用于算真实包功耗。
· 风扇 / EC / PWM：代码中不存在任何写入。决策树里的 TargetFanPercent 只是动作字段，未落到硬件；
  风扇转速由固件/EC 按温度曲线自行调节，软件只能通过降低发热间接影响它。
· 电源计划 / 最大频率 / 电压 / 倍频：软件不碰。

== 3. 写入能力探测（0x610 同值写回 → 回读 → 恢复）==
结果           : WriteFailed
详情           : 驱动拒绝写入（HRESULT 0x80070002，返回条目 0）：常见原因是被 BIOS/HVCI 拦截，或该 MSR 在模块白名单之外
判定           : 本机不可写 0x610 → 软件对 CPU 寄存器的所有写入都不会生效；跳过写入式 A/B

== 7. 关键判定 ==
① 满载是否触及固件功耗墙 : 峰值包功耗 30.5W / 固件 PL1 45.0W = 68%
   → 本机在该负载下根本没顶到 PL1 天花板。把 PL1 调高（如 49W / 65W）不会产生任何可观测差异，
     这正是『智能调优没有直观感受』的核心原因之一：调的是上限，而实际功耗远在上限之下。
② 决策值是否落到寄存器     : 决策 PL1 均值 46.4W / 0x610 实读均值 45.0W
   → 软件算出了不同的目标，但寄存器没变：决策树只是『遥控建议』，写入需要双开关 + 驱动支持。
③ 热模型校验               : 空载→满载 ΔT=7.67°C / ΔP=13.67W = 短时斜率 0.561 K/W；稳态标定 Rth=0.985 K/W
   → 短时斜率通常小于稳态 Rth：40 秒还没走到热稳态（本机 Tau≈8h，热容很大），
     两点稳态法测出的 Rth 只适合做长期稳态外推，不适合解释瞬时升温速度。
④ 低负载对照（2 线程 vs 6 线程）:
   稳态温度 60.6°C vs 满载 65.0°C（ΔT=-4.48°C）；包功耗 22.6W vs 29.9W（ΔP=-7.31W）
   核频 3.42GHz vs 3.41GHz；平均负载 46%（逐拍见 CSV）
   → 这段是『改变负载』而非『软件改参数』的对照：功耗一降，温度就跟着降，量级清晰可测。
     它说明 ThermalPilot 若真能把 PL1 压到实际功耗之下，效果是看得见的；
     但本机 0x610 写入链路不通（第 3 节），软件目前做不到这一步。
⑤ 定量外推（若写入可用）   : 把 PL1 从 45.0W 降到 24.8W，按稳态热阻 0.98 K/W，长期稳态温度预计下降约 5.1°C；
   把 PL1 放宽到 65.0W 则预计 <1°C 变化（实际功耗 29.9W 远低于墙）。
   注意：这是稳态估计，短时实测降温幅度会因热容偏小（见 ③）。

== 8. 结论汇总 ==
1) 软件真正尝试写入的只有 MSR 0x610 的 PL1 / PL2 / Tau（以及本机不可用的 0x774 EPP）；
   风扇 / EC / PWM / 电源计划 / 电压 / 倍频一律不碰。
2) 本次实测：0x610 同值写回即被驱动拒绝（0x80070002），全程 0 次成功写入，
   且『允许写入 MSR』默认关闭、自动接管被熔断条件挡住 —— CPU 寄存器始终是固件默认值。
3) 没有直观感受的四层原因：
   a. 写入链路不通 + 双开关未开 → 参数根本没改；
   b. 满载峰值功耗仅固件 PL1 的 68% → 调高上限无效；
   c. PL1 是长时平均功耗墙（Tau≈8h 量级），属于慢变量，短时操作看不出变化；
   d. 风扇由 EC 按温度曲线自动调速，软件不直接拨风扇，只能间接影响。
4) 要有可观测效果的前提：换成支持写 0x610 的签名模块，并把 PL1 压到低于实际满载功耗；
   本机约需 <30W，按 Rth≈0.98 K/W 预计稳态降温 5°C 以上，风扇随之降速。
