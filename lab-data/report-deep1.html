一句话结论

热模型本身没问题——温度几乎瞬时跟着功耗走，T ≈ 24 + 2.08·P 就能解释全部观测； 但这套实验想验证的控制杠杆（powercfg 最大处理器状态）在这台机器上完全无效： cap 从 100% 压到 40%，功耗、频率、温度三者一个都没动。所以不是“模型不合适”，是执行器坏了，模型没有可驱动的东西。

① 温度轨迹

两条曲线对照着看就是全部问题：载荷曲线有三段台阶（cap100 / cap70 / cap40），功耗曲线却是一条平线。 温度在同一水平线上下抖 ±2℃，说明 CPU 一直在同一个工作点，cap 根本没有被固件采纳。

⑤ 模型该采用什么形式

  • 静态映射够用：T = 23.9 + 2.08·P（P 为实测封装功耗）。空闲簇 10.5W→45.8℃，满载簇 34.9W→96.7℃，两点定一条线。
  • 动态项可以砍掉：温度在换段后 ≤ 1.7 s（一个采样间隔） 内就落到稳态 ±5℃ 以内，300 秒窗口内没有任何缓慢漂移。 一阶惯性 dT/dt=(T_ss−T)/τ 里的 τ 在 1 秒量级——这是 die 自身的热容，不是散热器的。
  • 于是“等稳态要 3τ”这条规则在这台机器上是白等：D1 给了 300 秒（≈300τ），和给 20 秒没有区别。 19.5 分钟里有 95% 的时间在重复测同一个点。
  • 原计划的 3/5/10 分钟快测，方向判断错了：我上一轮担心“段太短、没走到稳态”， 但这台机器的温度本来就是秒级收敛的，短实验的限制不在时间，而在每个功率点必须是真稳态。

⑥ 热阻分解：瓶颈不在风扇

  • 满载稳态 96.7℃，停机后 1 秒内跌到 ≈48℃，随后 300 秒一直停在 46–50℃。
  • 那 48℃ 就是散热器（热管+鳍片）在 35W 下的温度，于是 R_die→散热器 = (96−48)/35 ≈ 1.37 K/W，R_散热器→环境 = (48−24)/35 ≈ 0.76 K/W。
  • 1.37 K/W 的“芯片→散热器”热阻高得异常（正常装配应在 0.1–0.3）。这是硅脂干涸/泵出或散热模组压不实的典型特征。
  • 推论：风扇那一侧最多只占 0.76 K/W，就算吹到无限大也只能把温度压到 ≈72℃。 真正该做的是换硅脂/重新压装——但这必须在验证风扇当前是不是已经满载之后才能下结论（见下一步）。

⑦ 这次运行暴露的三个工程缺陷

  • NBFC 被实验自己关掉了：实验计划里没写风扇档位的段会调 RestoreFanDefault()， 而它执行的是 nbfc stop——这个命令会停掉 NBFC 服务，不是“交回自动控制”。 结果第 1 分钟之后 NBFC 就下线了，整场测试实际跑在 BIOS/EC 风扇曲线上。 正确的“交回自动”是 nbfc set -a。
  • 风扇占空比旁路采样只成功了一行：服务被关掉后 nbfc status 全部返回空，200 行里 199 行没有数据。 所以“温度平台是不是因为风扇没拉满”这个问题，这次答不了。
  • 采样间隔 1.65 秒慢于热响应：Read() 读全量传感器要 ~650ms，再 Sleep(1000)。 τ 在 1 秒量级时这个采样率已经抓不住上升沿，只够看稳态。下次要么把 Sleep 降到 200ms，要么只读 CPU 相关传感器。

⑧ 下一步（一次 9 分钟的运行就能定生死）

  • 先修执行器：把风扇改成“强制档位”而不是交给固件——用 NBFC 把占空比钉在 100% 和 55% 各跑 3 分钟。
  • 要回答的问题：同一功耗下，风扇 100% 比 55% 能低多少度？ 若差 ≥8℃，说明风扇杠杆真实可用，产品就围绕“风扇 + 有限的降频”做； 若差 ≤3℃，说明瓶颈在硅脂/压装，软件无解，必须让用户去换硅脂。
  • 顺带验证：修好 NBFC 的 set -a / 步进量程（本机 Fan speed steps = 197， 而代码里把百分比直接当寄存器值写，1%↔1 步是错的），并让旁路采样真正工作。
